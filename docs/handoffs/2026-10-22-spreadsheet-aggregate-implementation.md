## Resulting behavior

MIN, MAX, AVERAGE and COUNT now accept one rectangular range in ordinary formulas,
case-insensitively, and compose with arithmetic. They ignore direct blanks/literal
text, include explicit zero and numeric formula results, and propagate computed errors.
COUNT of no numeric members is zero; the other functions return typed NoNumericValues,
displayed as “No numeric values in this range.” Strict SUM text/blank/error ordering
is unchanged. MIN/MAX normalize numeric output, including equal representations and
signed zero. No aliases, scalar argument lists or generic function registry were added.

The canonical graph retains generic Blank separately from Input(0). Scalar Blank
still evaluates to zero; direct membership classification excludes it. Anchor creation
and Clear install Blank; entering zero changes the definition and invalidates consumers.
Both persistent and scalar snapshot definitions preserve kind. Frozen scalar exports
and hosted boundaries refuse unsupported markers rather than erasing their meaning.
Selection-aware workbook transfer carries a validated blank-slot overlay over zero
skeleton placeholders. Its internal transfer version is 3; that is not a change to
private application protocol v4 or hosted v1.

New operation-bearing range tokens reuse selection geometry, dependencies, invalidation,
cycle checking, row-major enumeration and immutable captures. Cache keys contain both
operation and SelectionId. SUM retains its original token and checked reduction path.
Core source-fault identity passes through new aggregate consumers without producer
knowledge entering the reducer. C# remains transport/presentation, including editor
and error-display handling; all calculations run in Rust.

AVERAGE uses a private four-limb signed-magnitude exact accumulator at scale 28, with
checked count and bounded final division. It selects the greatest fitting scale from
the original exact sum, rounds nearest with exact midpoints away from zero, and
normalizes. MAX/MAX returns MAX; large cancellation does not overflow an intermediate
Decimal96 sum. This is not a public numeric type, bigint dependency or change to
ordinary arithmetic/division. Existing work, cancellation and allocation-domain
accounting remain in use, without capacity increases. A final ownership review added
a separate 192-byte-per-token reservation for operation-bearing cache/set metadata,
leaving pure SUM admission unchanged; final platform reruns include this reservation.

## Files and clipboard

New saves are **PIVOTWB5**. The bounded WB4 reader validates old structure/checksum,
SUM tokens and content/graph correspondence under legacy rules before reconstructing
Blank from workbook metadata. Successful Open is clean and the next Save writes WB5.
WB1/2/3 remain unsupported; failed Open retains live workbook, path, dirty state and
checkpoint. Unknown aggregate tags/kinds and inconsistent blank overlays reject.

A genuine legacy fixture was written using the preserved accepted ADR-0020 Rust
binary, then stored as `tests/fixtures/legacy-wb4-aggregates.hex` in the document
crate. Its decoded bytes have SHA256
`8c407e9a8cf2bfecf57996d4dc296b5890dd40e934e5ea55bf20c2e3461630dc`.
It contains literal text, a cleared anchor, numeric values, valid/strict-error SUM,
a scalar blank reference and an invalid draft. Tests preserve CellIds, SUM behavior,
rejected content, blank/zero classification and WB5 resave/checkpoint behavior.
The fixture is not a WB5 file with its magic changed.

PIVOTCB2 remains source/effective-coordinate based. New functions use its existing
endpoint annotations for native/TSV copy, dollar flags, reversed ranges and overlap;
malformed native data still cannot fall back to text. A direct probe against the
preserved old reader rejects a new MIN native payload and a WB5 file without changing
its existing root/value. Evidence: `artifacts/aggregate-design/old-reader-compatibility.json`.
The portable old-reader fixture runs on every platform; the Windows binary probe is
supplementary and not a Mac build dependency. Private application v4, hosted v1 and
model-database formats are unchanged. Experimental structured proofs remain non-savable.

## Remaining gate and limits

The completed Mac/APFS run validates the existing WB4-reading implementation.
The interim parent response requires WB5-only read/write before final ADR-0021
acceptance: remove migration, retain current-format invariant tests and explicit
old-version rejection, then validate the modified source on all three platforms.
This is a condition within ADR-0021, not an accepted milestone or separate cleanup
milestone. The interim response explicitly was not a new implementation assignment.
No compatibility code was changed during this evidence review. Do not mark the bounded milestone accepted or start another
feature. The previous Windows ClipboardChecklistAsync null-destination observation
remains unresolved; it did not recur in these Windows runs. Preserve focused
recurrence diagnostics rather than weakening tests or redesigning the clipboard.
Historic WSLg startup abort, Windows-mounted-path Save uncertainty and Linux viewport
p95 exception remain separate. No recurring manual replay requirement was introduced.

No MEDIAN/MODE/aliases, formatting, Undo/Redo, row structural edits, capacity increase,
permanent structured-data language/persistence, connector, scheduler or collection
runtime has been added. The tested WB4 compatibility exception is superseded as a target policy by the
interim parent correction below; it remains present in the tested runtime. Final
implementation acceptance is pending the correction and its validation.
